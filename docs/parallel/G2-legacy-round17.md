## 66. `LamTelescopeN`

For every binder list `sp` and non-lambda body `b`: a successful run of
`lambdaTelescope (lams sp b) k` is a successful run in some `mctx` of
`k fvars (b.instantiateRevRange 0 fvars.size fvars)`,
`fvars = (ids.map .fvar).toArray`, with `DeclsOpen mctx sp ids #[]` (the
`j`-th variable declared with user name `nⱼ` and type
`dⱼ.instantiateRevRange 0 fvars'.size fvars'`, `fvars'` the earlier
variables accumulated by `push`). Two points where the statement is a
reformulation of the code and not its text: the final array is the code's
`push` chain written as `(ids.map .fvar).toArray`; and "still found in the
final local context" uses the distinctness of the fresh variables.

## 68. Item 3 — Bool, and a mismatch at width one

Read (`inferHWTypeStep`, `Elab.lean` 539–551; reached by
`inferHWTypeFromSignal` when not symbolic through
`inferHWTypeWithDimensionsStep`, line 694):

* `Bool ↦ some .bit`. The certified `.bool` binder binds
  `bindInputPort id nm.toString .bit`. They agree: a `Signal dom Bool`
  binder is covered by the list theorem with kind `.bool` and the premise
  `InfersHW T .bit` (`kindHW .bool = .bit`).
* `BitVec w ↦ some (if w == 1 then .bit else .bitVector w)` (line 549). So a
  `Signal dom (BitVec 1)` binder gets a `.bit` port from the legacy walk; the
  certified `.bits 1` binder gets `.bitVector 1`. **Mismatch**: for kind
  `.bits 1` the premise `InfersHW T (.bitVector 1)` is false of the real
  oracle; with kind `.bool` the port agrees but the source value is a
  `BitVec 1`, not a `Bool` (`prepare` puts it in `bools`, `Admissible` asks
  `encodeBool`). The bridging lemma would be: a `.bit` port carrying
  `(x : BitVec 1).toNat` is the `.bool` binder at `x.getLsbD 0` /
  `x = 1#1`, plus the corresponding transport of the leaf's meaning — not
  written. Width-one vector binders are outside the covered domain.
