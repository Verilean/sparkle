# Certified acceptance: first F1 milestone

Implemented 2026-09-24. This is a proof-carrying acceptance boundary, **not a
completed CompCert-class compiler proof**. The DSL reifier remains a partial,
unverified meta-program. The underlying generator and its performance are unchanged.

## Contract and general theorem

`Tools.CertifiedRoundtrip.Certificate source` contains the exact generated text,
width environment, chronological input/state seed, initial register state, output
port, three bodies, and mandatory proofs for original replay, optimized replay,
reparsed replay, and parsing that text to that reparsed body.

`Certificate.sound` proves, for any certificate and any finite horizon `K`, that
`runText` succeeds and the output at every `t < K` equals `source t`.
`runText` invokes the shipping parser on the certificate's bytes and then runs
the returned body with `runModule`. It does not execute a substituted body without
using the parse equality. The theorem covers `K = 0` as well as positive horizons.

`accepted_sound` quantifies over any input type and any producer returning
`Except String (Certificate (source input))`: every successful artifact has that
property. This is a composition theorem for proof-carrying results. Its strength
comes from the required proof fields; it is **not** a proof of the implementation
of the producer, nor a verified Boolean certificate checker or a proof that the
producer terminates or succeeds on all well-formed DSL inputs.

The seed, width environment, initial state, zero initial memory, and output port
are explicit parts of the contract. This does not quantify over arbitrary reset
or clock behavior independently of the existing Signal/replay semantics.

## Use

```lean
import Tools.CertifyShared

-- f is a supported circuit-do definition in this namespace.
#certify_shared_roundtrip f => f_certified

-- The resulting definition takes f's Signal inputs as parameters.
-- For any inputs and horizon K:
-- (f_certified inputs).sound K
```

For proofs already generated by `#verify_elab_deep`, use
`#seal_shared_roundtrip f => f_certified`. Invoke it in the namespace containing
the generated family, or open that namespace. The command verifies that the
replay's source observation is definitionally the requested function, specialized
to `defaultDomain`. A single-field BitVec Signal output structure is supported
(including crc16); multiple output fields and Bool outputs are outside this API.

Both commands require all of `_sdeep_trace`, `_sdeep_signal_run`,
`_sdeep_signal_runOpt`, `_sdeep_signal_runRT`, `_sdeep_text_parses`, and
`_sdeep_text`. Missing links produce an error, not an accepted partial chain.
Before emitting the certificate they audit the proofs, check matching source and
execution parameters, and reject previous elaboration errors. The final definition
is submitted to Lean's kernel. The success marker is `CERTIFIED_ROUNDTRIP`, not a
bare PROVEN line.

## Trust and limits

The generic soundness theorems use only standard axioms. Concrete certificates
retain the source trace's `bv_decide` auxiliaries and the parse theorem's
`native_decide` auxiliary. The adapter restricts auxiliary owners to the specific
trace and parse theorem, and rejects `sorryAx` and unrelated axioms. It also allows
`Lean.ofReduceBool` explicitly, as in the existing trust boundary.

The certificate's final text soundness theorem genuinely depends on the parse
oracle; unlike `_signal_runRT` alone, it composes both links. Source-specific
proofs remain essential. No claim is made that all circuits satisfying a syntactic
description can be certified: during implementation, a small mux counter reached
an existing shared-generator trace-proof failure; the new command correctly
refused it. The successful entry-point test uses an add/xor sharing circuit.

This is **parser-relative text semantics**, not independent SystemVerilog
semantics or a proof of the shipping printer/parser inverse. In particular,
crc16's forward SV theorem still skips the M4 shift rule, while its complete
roundtrip certificate succeeds. The command never labels it forward-certified.
The original/optimized proof fields compare behavior; they do not assert that
the optimizer and printer implementations themselves are universally correct.

## Verified combinational frontend (second F1 milestone)

`Tools/VerifiedBlock.lean` adds a total compiler for **typed combinational
let-blocks**, reusing `CExpr` and `CExpr.compile_correct`. This is a new explicit
source API, not a proof of the existing shallow `circuit do` reifier.

`Block Γ w` has a return expression and a binding constructor. A binding extends
the typed context for its continuation: later wires are inaccessible by
construction, and a compiled binding emits one assignment rather than
substituting its expression at every use. All existing CExpr operations are
available, including mux, comparisons, slices and arithmetic. Registers, loops,
memories and multiple outputs are not in this grammar.

`Block.compileChecked` returns an IR statement list or a named error. It checks
input/output/binding widths and freshness of each binding against its live
context. `compileChecked_complete` proves acceptance for every block satisfying
those finite syntactic conditions. `compileChecked_sound` proves that every
successful compilation satisfies the existing `RunCorrect` contract, for all
input traces and all finite horizons. Unlike `accepted_sound`, this theorem does
**not** take a per-program execution-correctness proof as an argument: its proof
inducts over the compiler's source syntax and over `runModule`'s cycle count.

The execution contract assumes that the caller's seed supplies the declared
input values at their names. Input names need not be injective; if they alias,
that premise requires their values to agree. Widths and names are explicit
compiler arguments. This proves the sequential IR assignment semantics, not
independent SV scheduling or validity of an arbitrary module port layout.

`Block.certify` supplies the original-body proof to the previous certificate API.
Optimized/reparsed execution and exact-text parsing still need downstream
evidence. The test emits a real module with the shipping printer; its parser
inlines a wire and adds a width mask. A second block plus a BitVec identity proves
that parsed body's behavior. The test uses an identity optimizer, **not** a new
universal proof of the shipping optimizer. Its final text theorem retains only
the parser oracle beyond the standard axioms; its compiler/replay theorems have
standard axioms only and no bv_decide/native_decide auxiliaries.

## Verified sequential frontend (third F1 milestone)

`Tools/VerifiedState.lean` extends the explicit typed source approach to
**one register of arbitrary width, shared combinational bindings, and one output**.
This milestone does not add register banks, memories or nested loops, and does
not change the shipping generator. `Machine Γ r w` contains a typed initial value
and a `Step (r :: Γ) r w`. The step returns both next-state and output expressions;
its let-bindings are emitted once and can be shared by both expressions.

The source recurrence is explicit: state 0 is `init`; output t is computed from
state t and input t; state t+1 is `init` when reset t is asserted, otherwise the
step's next-state result. An enable/hold is expressed by a mux. The compiler emits
assignments and an actual IR register statement. `Machine.compileChecked_sound`
proves the existing `RunCorrect` proposition for every successful compilation,
every input and sampled reset trace, and every finite horizon. The proof tracks
the register invariant through `applyNexts` and `runModule`, not just an equality
between expression evaluators. `compileChecked_complete` establishes acceptance
under the finite naming/width checks. These theorems have standard axioms only.

The checked layout prevents input/register/reset overlap and prevents bindings
or the final output assignment from overwriting values needed for register-next
evaluation. Input-input aliases remain permitted under the same seed-agreement
contract as the combinational frontend. `SeedCorrect` requires the caller to
preserve the current register and supply the declared inputs and reset. The
initial target environment must contain `init` at the register name. Clock edges
are abstracted as IR cycles; the theorem does not validate port declarations or
asynchronous events between clock edges. Only the cycle-sampled reset contract
is claimed, including when reset is asserted on the first cycle.

`Machine.certify` connects the general compiler proof to the certificate API.
`runModule_congr_step` and `RunCorrect.of_stepEq` compose downstream passes that
preserve an entire IR step (outputs, register updates AND memory updates).
The accumulator test uses the shipping printer and parser. The parser reorders
two independent assignments and changes reset kind to asynchronous. A theorem
proves their whole-step equality for all environments and memories, then lifts
it to all runs. This is valid because existing IR semantics ignores reset kind;
it does **not** establish independent SV event-semantics equivalence. The final
text theorem retains only the parser oracle beyond standard axioms. As in the
combinational test, the optimizer slot is identity rather than the shipping pass.

## Shipping Signal/circuit-do bridge (fourth F1 milestone)

`Tools/VerifiedCircuit.lean` connects the shipping **single-register
`runCircuitH`** to `Machine`, using the actual `Signal.loop`, register handles,
pending-write accumulator and `packRegister`. `runCircuitH_eq` is a general loop
theorem. Its `BodyMatches` hypothesis says that for every live register signal
and every time, the body's result and pending write equal the typed step's
output and next state (including the sampled reset mux). This is a pointwise
combinational correspondence, not a trace theorem supplied as a premise.

`compileChecked_signal_sound` composes that bridge with the verified state
compiler; `certifyCircuit` returns a certificate indexed by the shipping
runner's actual Signal observation. General and concrete source-to-IR theorems
use standard axioms only, without a SAT/native-decide auxiliary.

`VerifiedCircuitTest` defines an enabled/resettable accumulator in actual
`circuit do` surface syntax. `surface_expands` is `rfl`, pinning the shipping
macro expansion to the body under proof; `body_matches` proves the pointwise
obligation for arbitrary inputs. `surface_replay` and `surface_text_sound` then
follow from the general theorems. The final text theorem uses the same real
printer bytes and parser oracle as the stateful test. A separate theorem
shows that a body reading the live register at t+1 fails `BodyMatches`.

**What remains manual:** selecting the typed machine and exposing/proving the
surface body's correspondence. No universal extractor from Lean syntax/Expr has
been implemented or verified. The IR is emitted by the new verified frontend,
not by a now-verified `Sparkle.Compiler.Elab`. This closes the Signal-loop bridge
for the supported template; it does not establish coverage of all `circuit do`
definitions or correctness of the shipping reifier.

## Total statement extraction (fifth F1 milestone)

`Tools/VerifiedSource.lean` supplies the previously missing general body
correspondence for a declared typed statement language. `Program Γ r w` contains
let-bindings, next-state writes, return and delayed bindings. Interpretation is
separate from extraction: expressions use shipping Signal combinators, delayed
bindings use `Signal.register`, and pending writes are threaded through statements.
`Source.body` submits the output and pending write with the explicit sampled-reset
policy through the actual register handle; `Source.run` uses `runCircuitH`.

`Program.extract` is structurally recursive and returns a typed `Step` or an
error. It carries a pending expression, initially the live register. Let-bindings
weaken its variable indices; `weaken_denote` proves absence of capture, including
a write followed by later bindings of the same width. No write means hold.
Duplicate writes are rejected even when separated by lets, matching the surface
macro's straight-line restriction. Delayed bindings have real source semantics
but are refused because they require another register.

`extract_iff_supported` proves extraction succeeds exactly for programs without
delayed bindings or duplicate writes (relative to its incoming write flag).
Naming/width checks are subsequent and may still refuse such a program.
`extract_correct` proves pointwise preservation; `Source.extract_bodyMatches`
derives the loop bridge's obligation for every successful extraction.
`Source.compile_sound` composes extraction and IR compilation into Signal-to-IR
correctness, with neither a manually chosen Step nor a body/trace theorem as a
premise. Seed and initialization plumbing remain explicit. All these generic
theorems are audited to use standard axioms only.

`Source.certify` connects to the artifact API. The test identifies the interpreted
source with the existing enabled/resettable `circuit do` accumulator by `rfl`,
then obtains its actual printed-text theorem without the old hand-written
`body_matches`. Parsing remains an evaluated oracle; the optimizer is identity
in this test.

**Representation boundary:** this is a typed-AST frontend, not a parser or
Lean.Expr reifier. The test's input AST is manually written; the `rfl` pin
validates it for one surface definition. General extraction FROM this AST is
proved, general conversion of Lean source TO it is not. The TODO separates these
obligations rather than marking all surface extraction complete.

## Automatic source reading with per-definition validation

`Tools/ReflectSource.lean` provides `#reflect_verified f => model`. It reads
the elaborated definition into a `Source`, creates input/reset functions, and
submits `model_source_eq` to the kernel. This equality pins the candidate's
actual `Source.run` to the requested definition for all its parameters.
The reader itself is unverified; acceptance requires standard axioms only.
A wrong candidate is rejected, and command failure restores declaration state.

The initial fragment is monomorphic, a direct `runCircuitH` body with one
BitVec register, constant initialization, BitVec Signal inputs/output and
optionally one Bool reset as the outer next-state mux. Expressions support
variables, constants, add/subtract/multiply, bitwise operations and mux with
a one-bit equality-to-one condition. Lets are unfolded, not shared: reading
refuses after 2048 visits. This is not the scalable shared-cone reifier.

`ReflectSourceTest` reads two existing surface definitions without handwritten
ASTs. The resettable accumulator uses `Source.compile_sound` to obtain replay
and an artifact for the shipping printer's actual text. Optimization is identity;
the parser remains an evaluated oracle. Reset-kind equality is only within
the cycle-level IR semantics, not external SystemVerilog event semantics.

## Validation and next milestone

- `CertifiedRoundtripTest`: shareX4/shareX8 certificates, source-to-parsed-text
  soundness, exact generated bytes, generic axiom audit, and rejection of missing
  parse/replay/optimizer links, wrong source, disallowed axioms, and changed text.
- `CertifySharedCommandTest`: the public command generates and seals a fresh
  small circuit end to end.
- `CertifiedRoundtripCrc16`: seals the shipping circuit's existing chain without
  rerunning its proofs, while retaining and checking the parse trust dependency.
- `VerifiedBlockTest`: universal-theorem instantiation, changing chronological
  inputs, overflow, shared references, mixed widths/mux, zero horizons/widths,
  collision and width refusals, shipping-printer text and programmatic axiom audits.
- `VerifiedStateTest`: universal sequential-compiler theorem, nonzero initial
  state, enable/hold, mid-run and continuously asserted reset, overflow, old-state
  output timing, zero horizon, naming/width refusals, shipping-printer roundtrip,
  all-environment step equivalence and axiom audits.
- `VerifiedCircuitTest`: actual macro expansion, pointwise body correspondence,
  arbitrary Signal-to-IR/text replay, a future-register-read counterexample, and
  source/artifact axiom audits.
- `VerifiedSourceTest`: all-program extraction/body theorems, actual surface
  replay/text, hold and pending-write capture avoidance, delayed-binding and
  duplicate-write refusals, downstream layout rejection and axiom audits.
- `ReflectSourceTest`: automatic ASTs, requested-source identity, generic replay
  and text, named refusals, fabricated-candidate rejection, axiom audits and
  absence of partial artifacts after refusal.
- All eight are required by `bench/xiangshan/ci_check.sh` after the shared tests.

F1 stays open for the shipping DSL. Typed statement extraction, its compiler and
the single-register runner bridge are proved. A bounded Lean Expr reader now
connects actual definitions by per-definition kernel validation. Reader coverage
and sharing remain open; no universal reader theorem is claimed. Register banks,
direct printer/SV correspondence and hierarchical semantics remain separate
milestones. No claim of a completed CompCert-class compiler is made.
