# 既存IPを保持してFGへ到達する設計方針

Issue: `sparkle-fg-circuit-strategy`（親 `sparkle-fg-final`）。2026-11-06 reviewer。
ユーザーの委任: 任意のLean記述を扱う必要はない。既存IPがコンパイルでき、回路になる記述に対してFGへ到達する妥協点を選び、必要な設計変更を進める。

## 1. 判断

現行の局所定理は再利用する。ただし、任意のLean定義を展開してから全残余に意味を与えることを、FGへの既定の道筋にはしない。
**回路として受け付ける有限の構文・演算を定め、受理した入力と出力の対応を検査／証明してから成功を返す経路**を優先する。
まず既存の生成器・reader・階層合成を使い、足りない証拠を生成する小さい縦断実装を作る。全コンパイラの書き直しは先行させない。

これは実装着手の方針決定である。新しい最終定理の完成、停止集合の採用、未記述のTRUSTEDの包括承認を意味しない。
通常の設計選択はこのユーザー委任の下でreviewer/coderが決める。既存IP維持と意味保存が両立しない具体例が出た場合に限り、その選択肢をユーザーへ戻す。

## 2. 現状と原因

- 台帳8649968e §12.24: FG 75（リーフ54 / 非リーフ21）、T1 57。数の減少には派生行・重複の除去も含まれる。最終定理の証明完了とは異なる。
- D.D-4 e37da005 §Trace: 235 rootの測定でSignal+BitVecの定義を停止してもcorpus全体には再帰子13が残る。一方、調べた3つのSignal rootでは再帰子・証明束縛・Type 0外が0、停止7 keyはDynに入る。
- Init/Std/Leanまで広く停止すると再帰子は0になるが、停止126 key中18はDyn外。停止するだけでは、その関数の意味を証明する義務は消えない。
- parametric 5e5c9bd2: gen5上で組立はできたが、hLの代わりにMemoFamily / MsgMvK / LamTelescopeNが必要。最終Hのwitnessと入力が一致しても、Hの意味保存の結論を証明したことにはならない。
- Q-B shardは置き場、Q-Cは条件付きの型付け補題を解決した。PTの型付け・関数性だけでは元のLean宣言の意味との一致やDeclConnectの存在は出ない。

したがって、工数だけの問題ではない。表現する対象と成功条件、意味を信頼する境界がまだ広く、局所的な前提の置換が増えている。

## 3. 保持する利用者の契約

1. 開始時点で成功する既存IPのtop・パラメータ・オプション・toolchain・SHAを固定一覧にする。テスト用235 rootと、以前の1369成功コンパイルの測定と、IPの一覧は同一視しない。
2. 既存のビルド／コーパス実行手順から必要IPを抽出する。新規則で落ちる各IPには原因と修正先を付け、未説明の除外をしない。
3. 外部ポート、幅、符号、クロック、reset極性・初期値、レイテンシ、メモリのread/write挙動を保持する。既定は生成物の一致。出力が変わる場合は差分理由と意味の同値を示し、既存simulation/vector検査も通す。有限テストは全入力証明の代替にはしない。
4. 燃料切れ・未対応構文・不正なパラメータ・証拠検査失敗は成功扱いにしない。黙って旧fallbackへ戻さない。保証外経路を残すなら明示的に区別する。
5. 保証の出力境界は現行のrunModuleTG/IRを起点に明記し、SV printerや合成器まで証明済みとは表示しない。IPのSV生成と実行回帰は別の受入条件として維持する。

## 4. 対応する記述と意味の境界

候補となる回路の核: 有限幅Bool/BitVec、静的な組・構造体、let、mux、有限回路の共有・階層呼出し、明示的なregister/feedback/memory。回路のfeedbackと、合成処理の非停止再帰は区別する。
幅・型・Natパラメータは合成時に具体化し、その後の回路IRでは有限の型付き演算として扱う。記号パラメータが必要なIPは一覧で特定し、必要な範囲を残す。
高階のmap/Applicativeや補助定義は、型・パラメータを具体化して回路の核へ落とす。任意の高階関数・宇宙多相な値を実行時の回路値として表すことは初期目標にしない。

推奨の最初の候補は、名前空間全体の停止ではなく、**具体化されたSignal/BitVec primitiveの適用単位での認識**である。
各primitiveには、正確な宣言・level・引数・結果型・値の意味・IR演算・時相/resetの対応を付ける。表の行を置くだけで意味を与えたことにはしない。
構造体のshardは引き続き使える。type/proof引数を消去する場合、依存する値や幅を落としていない証拠が必要。コーパスに現れた名前だけを認める方式は一般定理の対象範囲の定義にしない。

## 5. 方式比較と選択順

| 方式 | 得られるもの | 費用・妥協 | 判断 |
|---|---|---|---|
| 現行の任意Expr carrierをType 1/宇宙多相へ広げる | 広いLean表現を扱える可能性 | 関数性・健全性・依存型・再帰子の再設計が大きい。既存IPに不要な一般性も払う | 必要IPが他案で扱えない場合に限定 |
| Signal+BitVec等の具体化済みprimitiveで展開を止める | 小さい有限回路の意味へ接続しやすい | primitiveごとの意味の一致が必要。名前空間停止だけでは不十分 | 最初の縦断候補 |
| 未対応／不正条件を検査して成功経路を狭める | runから不変量が出る。未使用の経路の証明を減らせる | 以前成功した非回路的入力はエラーになる。必要IPは落とせない | ユーザー委任の範囲で採用方向 |
| 既存生成器が証拠を出し、小さい純粋checkerで検査 | cache/MetaMの実装全体への依存を減らせる可能性 | checkerの健全性と元ソースへの結び付けを証明する必要がある | 現行run証明より小さくなる箇所で採用 |
| コンパイラ全体を純粋な状態機械へ書き直す | IO.Ref/Meta状態の法則を大きく減らせる可能性 | 移植と互換性確認が大きい | 当面選ばない。必要なら狭い部分だけ置換 |

checker案の成功条件は「IRの幅が合っている」だけでは足りない。元の同じ宣言の認識・正規化・primitiveの意味から、出力IRの意味までの対応を検査する。
一般のプログラム同値判定を作るのではなく、限定した翻訳規則の導出を検査する。規則の健全性を先に一度証明する。

## 6. ゴールの形

次は概念上の形で、既存のFG型との対応を最初の実装で固定する:

```
compileCircuit env source params = .ok artifact
  → ∃ sourceMeaning,
      SourceDenotes env source params sourceMeaning
      ∧ HasConcretePackage artifact
      ∧ ObservationsEqual sourceMeaning artifact
```

全対応入力／全入力列に対する一般定理とし、存在するsourceMeaning・packageと、clock/resetを含む観測の対応を実証する。
SourceDenotesを生成出力の意味から逆定義してはならない。未解決のDeclConnect、DataOk、coverage、各設計の「正しい」を成功の外の仮説へ移して終わらせない。
同じ環境・ソース・パラメータ・生成物を結ぶことをrootで検査する。

残せる信頼境界は、版固定され、内容が具体的な外部実装／primitiveの境界だけである。意味一致を公理に置く場合は、型付けのみの公理と区別して一覧・用途・実装との照合を示す。
新しい境界の文面はreviewerが判断する。FG/T1の残りをTRUSTED欄へ移すだけでFG=0と報告しない。旧台帳、新FGへの対応、残る信頼境界を併記する。

## 7. 最初の実行単位

### S0: 同じ土台とIP契約を固定する（すぐ着手）

coderは最新gen5/Elabの統合SHAを1つ選び、必要IP一覧とbaselineを記録する。
全ブランチを一括mergeせず、承認済みの必要commitを接続する。比較資料だけを長く作らず、以下S1の実装に直結させる。

### S1: 最初の縦断を通す（最優先）

e37da005で測った3つのSignal rootと、一覧から選んだ実IP top 1件を起点にする。
具体化済みSignal/BitVec primitive、固定source semantics、既存reader/genDataとIRの接続を実装する。
最初に完全な結論と証拠の受渡しをLeanで型付けし、欠ける箇所は名前付き引数として条件付きで並行に埋める。
受理条件は「コンパイルできる」だけでなく、この経路についてSourceDenotesの存在と意味保存がkernelで成立すること。
S1は方式の検証であり、4件だけの定理でFGを完了しない。

### S2: FG/T1の残りを成功検査・構成・境界へ割り当てる

各行について、(a)既存定理をrootへ接続、(b)成功時の検査から導出、(c)核の生成構成から導出、(d)具体的な外部境界、のいずれかを選び、元の行ID・同じ消費者・追加義務を書く。
特にENV/cache、reader production↔model、ReachCover/genData成功、階層の配線・幅・名前、Post、DeclConnectを束で扱う。
検査できるものを先に実装するが、意味保存そのものを単なるBool検査の名前に変えてはならない。
IR検査で不要になるIO/Meta法則は、実際に最終証明のclosureから外れることを確認して初めて除く。

### S3: 必要IP全件と一般定理を揃える

S1を有限の構文規則の帰納法へ一般化する。必要IPの未対応構文をkey/経路ごとに追跡し、必要な構文だけを足す。
成功判定が証拠を供給するところまで接続し、kernelのaxiom/closure監査、非空虚な実IPの証拠、固定SHAの全体build・回帰を揃える。
対象を狭めた分は旧FGとの差分として明示する。既存IPの未説明の失敗、隠れたfallback、循環した意味の定義、未供給の設計別前提があれば最終受理しない。
